# Deliverables Guide

Use this reference to keep outputs consistent.

## 1. 竞品扫描记录 structure

Recommended sections:

1. purpose
2. product scope and assumptions
3. competitor buckets
4. selected competitors and why
5. source notes by competitor
6. immediate observations
7. interim judgment

The file should answer:

- who was scanned
- why they were chosen
- what current evidence says
- what stood out immediately

## 2. 竞品分析报告 structure

Recommended sections:

1. conclusion first
2. market verdict
3. expanded strengths for the product
4. competitor weaknesses and what they reveal
5. improvement priorities
6. product-shape implications
7. source list

The file should answer:

- how the product looks against the current market
- what strengths should be claimed more clearly
- what gaps are now undeniable
- what to change first

## 3. 产品增强建议 structure

Recommended sections:

1. design principles
2. P0 changes
3. P1 changes
4. P2 changes
5. expected user outcome

The file should answer:

- what to implement next
- where in the product or repo it should land
- what concrete effect the change should have

## 4. Evidence rules

- Cite links for current competitor claims.
- Use dates for current-market statements.
- Label inference explicitly.
- Keep the source list in the report even if the scan log already includes links.
